# Student Management System (Система управления расписанием репетитора)

Бэкенд-сервис для автоматизации работы индивидуального преподавателя: управление профилями учеников, сеткой слотов, процедурой бронирования, отмены и посещаемости занятий.

## Технологический стек
* **Java 25**, **Spring Boot 3**
* **Spring Data JPA**, **H2 Database** (файловая, профиль `dev`)
* **OpenAPI / Swagger UI**
* **JUnit 5**, **Mockito**, **AssertJ**

## Архитектура
Приложение спроектировано по принципам **Onion Architecture** (Чистая архитектура):
* `domain` — доменные сущности и интерфейсы репозиториев (бизнес-правила без внешних зависимостей).
* `application` — прикладной слой, содержащий 12 сервисов бизнес-логики и DTO.
* `infrastructure` — инфраструктурный слой (REST-контроллеры, JPA-сущности, адаптеры БД).

## Основные сервисы (Application Layer)
1. `StudentRegistrationService` — регистрация новых учеников.
2. `StudentAdminService` — администрирование данных студентов.
3. `StudentServiceImpl` — общее управление профилями учеников.
4. `SlotManagementService` — создание и управление временными слотами.
5. `ScheduleViewService` — просмотр и формирование расписания.
6. `BookingService` — логика бронирования занятий.
7. `CancellationService` — отмена и замена слотов.
8. `AttendanceTrackingService` — фиксация посещаемости и проведенных уроков.
9. `NotificationService` — генерация сообщений и уведомлений.
10. `PricingService` — расчёт стоимости занятия и индивидуальные цены.
11. `StudentSubjectService` — предметы ученика и проверка, что занятие записано на закреплённый предмет.
12. `ReferralService` — реферальная программа, активация после первого занятия и скидка 1800 ₽.

## Запуск приложения

1. Клонировать репозиторий:
   ```bash
   git clone https://github.com/SuperPuper7565/StudentManagementSystem.git
   cd StudentManagementSystem
   ```

2. Запустить бэкенд:
   ```bash
   mvn spring-boot:run
   ```

3. Открыть Swagger UI: <http://localhost:8080/swagger-ui.html>.

По умолчанию активен профиль `dev`. Файловая H2 создаётся в `./data/tutoringdb`
и сохраняет данные между перезапусками. Профиль `test` использует in-memory H2.

## Стоимость занятий

Стоимость рассчитывает только сервер. Клиент не передаёт цену при регистрации:
поле `lessonPrice` игнорируется, базовая цена задаётся в `application.yml`.

Правила:

- базовая цена — **2000 ₽** за занятие 90 минут;
- первое пробное занятие ученика — **1000 ₽** для всех;
- индивидуальная цена (например, **1500 ₽** по знакомству) задаётся администратором;
- занятия по двум предметам — **1800 ₽**; скидка начинает действовать после первого
  посещённого занятия по второму предмету и распространяется на все дальнейшие занятия;
- при трёх и более предметах цена остаётся **1800 ₽** и дальше не снижается;
- реферал — **1800 ₽** обоим после первого посещённого занятия приведённого друга;
  первое занятие друга всё равно стоит **1000 ₽**;
- итоговая цена — минимум из применимых правил, скидки не суммируются;
- пробное доступно, пока у ученика нет активного пробного бронирования и посещённых занятий;
- отмена пробного до урока возвращает пробную цену, посещение или «не пришёл» расходуют её;
- цена фиксируется в `Booking.price`, `Booking.priceDetails` и `Booking.isTrial` в момент бронирования;
- старые записи сохраняют цену, рассчитанную при их создании.

`GET /api/v1/students/{id}/price` дополнительно возвращает `trial` и `appliedRules` —
какое правило победило (`TRIAL`, `INDIVIDUAL`, `MULTI_SUBJECT`, `REFERRAL`, `BASE`).

### Предметы и бронирование

Основной предмет задаётся при регистрации и сохраняется в `students.subject`.
Дополнительные предметы хранятся в таблице `student_subjects`. Предмет бронирования
обязателен, сохраняется в `bookings.subject` и должен быть закреплён за учеником.
Слоты общие для всех предметов.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/students/{id}/subjects` | список предметов ученика |
| `POST` | `/api/v1/students/{id}/subjects?subject=Физика` | добавить предмет (нужен `X-Admin-Key`) |
| `DELETE` | `/api/v1/students/{id}/subjects?subject=Физика` | удалить дополнительный предмет (нужен `X-Admin-Key`) |

Основной предмет удалить нельзя. Если после удаления предмета по оставшимся предметам
посещён только один, скидка `MULTI_SUBJECT` перестаёт применяться к новым расчётам;
уже созданные записи сохраняют свою цену.

```bash
curl -X POST "http://localhost:8080/api/v1/bookings?studentId=1&slotId=2&subject=Математика"
```

Бот показывает список предметов ученика при выборе слота и передаёт выбранный предмет
в API. Старые бронирования без предмета продолжают хранить свою цену, но не участвуют
в расчёте скидки за второй предмет.

### Реферальная программа

Реферал создаёт только преподаватель. Ученик не может назначить скидку сам.
Один ученик может быть приглашён только один раз; приглашение самого себя запрещено.
После первого занятия приглашённого с `attended=true` реферал активируется для обоих,
и следующие занятия стоят **1800 ₽**. Первое занятие друга по-прежнему стоит **1000 ₽**.
Если друг уже посещал занятия на момент создания реферала, реферал активируется сразу.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/referrals?referrerId=1&referredId=2` | создать реферал |
| `GET` | `/api/v1/referrals` | список рефералов |
| `POST` | `/api/v1/referrals/{referredId}/activate` | активировать вручную |
| `POST` | `/api/v1/referrals/{referredId}/cancel` | отменить вручную |
| `DELETE` | `/api/v1/referrals/{referredId}` | удалить реферал |

Все методы требуют заголовок `X-Admin-Key`. Статусы реферала: `PENDING`, `ACTIVE`,
`CANCELLED`. Снятие посещаемости не откатывает уже активный реферал: для исправления
используйте отмену или удаление реферала. Отменённый реферал не активируется
автоматически при следующих посещениях.

```bash
curl -X POST "http://localhost:8080/api/v1/referrals?referrerId=1&referredId=2" \
  -H "X-Admin-Key: $ADMIN_API_KEY"
```

### Эндпоинты цен

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/students/{id}/price` | актуальная цена для ученика |
| `PUT` | `/api/v1/students/{id}/pricing` | назначить индивидуальную цену |
| `DELETE` | `/api/v1/students/{id}/pricing` | убрать индивидуальную цену |

Для `PUT` и `DELETE` нужен заголовок `X-Admin-Key`. Ключ задаётся переменной
окружения `ADMIN_API_KEY`. Если переменная не задана, административные операции
с ценами возвращают `403`.

Пример:

```bash
curl -X PUT http://localhost:8080/api/v1/students/1/pricing \
  -H "Content-Type: application/json" \
  -H "X-Admin-Key: $ADMIN_API_KEY" \
  -d '{"individualPrice":1500.00,"reason":"по знакомству"}'
```
