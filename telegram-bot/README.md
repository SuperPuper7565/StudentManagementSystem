# Telegram-бот для Student Management System

Отдельный клиент к Spring Boot-сервису `StudentManagementSystem`. Бот позволяет ученикам
регистрироваться, смотреть свободные слоты, записываться на занятия и отменять записи,
а преподавателю — создавать слоты, смотреть список учеников и отмечать посещаемость.

Бот не меняет бэкенд и общается с ним только по REST API.

## Что умеет

### Для ученика
- пошаговая регистрация: имя, фамилия, предмет, класс, цель, цена, формат занятия;
- привязка к уже существующему `studentId` (если профиль создан через Swagger/админку);
- просмотр свободных слотов с пагинацией;
- запись на слот в один клик;
- список своих записей;
- отмена записи с подтверждением;
- просмотр профиля.

### Для преподавателя (`ADMIN_IDS`)
- создание слота с проверкой формата и будущего времени;
- просмотр всех учеников;
- отметка посещаемости по записям, созданным через бота, или по ID вручную;
- доступ к тем же разделам, что и у ученика (если преподавателю нужен профиль — его можно
  создать или привязать).

## Требования

- Python 3.11+ (проверено на 3.14);
- запущенный бэкенд `StudentManagementSystem` (по умолчанию `http://localhost:8080`);
- токен Telegram-бота от [@BotFather](https://t.me/BotFather);
- свой Telegram ID (например, из [@userinfobot](https://t.me/userinfobot)) — для админ-доступа.

## Быстрый старт

### 1. Запустить бэкенд

Из корня Java-проекта:

```bash
cd StudentManagementSystem
mvn spring-boot:run
```

Проверить, что сервис доступен: <http://localhost:8080/swagger-ui.html>.

> База H2 у бэкенда in-memory: после перезапуска сервиса студенты, слоты и записи
> пропадают. Это ограничение самого сервиса, а не бота.

### 2. Настроить бота

```powershell
cd telegram-bot
py -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Откройте `.env` и заполните:

| Переменная | Обязательна | Описание |
|---|---:|---|
| `BOT_TOKEN` | да | токен от `@BotFather` |
| `API_BASE_URL` | нет | адрес бэкенда, по умолчанию `http://localhost:8080` |
| `ADMIN_IDS` | нет | Telegram ID преподавателей через запятую |
| `DATABASE_PATH` | нет | путь к SQLite-базе бота, по умолчанию `data/bot.sqlite3` |
| `REQUEST_TIMEOUT` | нет | таймаут HTTP-запросов в секундах, по умолчанию `10` |
| `LOG_LEVEL` | нет | `DEBUG`, `INFO`, `WARNING`; по умолчанию `INFO` |

Для Linux/macOS активация окружения: `source .venv/bin/activate`, копирование:
`cp .env.example .env`.

### 3. Запустить

Из папки `telegram-bot`:

```powershell
python -m tgbot
```

Или из корня проекта, где лежит `run-bot.cmd`:

```powershell
.\run-bot.cmd
```

`run-bot.cmd` сам переходит в `telegram-bot` и использует локальное `.venv`.
Если PowerShell блокирует `run-bot.ps1` из-за Execution Policy, используйте `.cmd` либо:

```powershell
powershell -ExecutionPolicy Bypass -File .\run-bot.ps1
```

В Telegram отправьте боту `/start`.

## Команды

| Команда | Кому | Назначение |
|---|---|---|
| `/start` | всем | главное меню / онбординг |
| `/register` | ученику | создать профиль ученика |
| `/link` | ученику | привязать существующий `studentId` |
| `/slots` | ученику | свободные слоты |
| `/bookings` | ученику | мои записи |
| `/profile` | ученику | профиль |
| `/cancel` | всем | сбросить текущий сценарий |
| `/help` | всем | помощь |
| `/admin` | админу | панель преподавателя |
| `/students` | админу | список учеников |

Основные действия также доступны кнопками — команды нужны в основном для быстрого доступа.

## Типичный сценарий

1. Преподаватель запускает бэкенд и бота, добавляет свой Telegram ID в `ADMIN_IDS`.
2. В боте: `/admin` → «Создать слот» → например, `25.10.2026 14:00`.
3. Ученик: `/start` → «Зарегистрироваться» → заполняет профиль.
4. Ученик: «Свободные слоты» → выбирает время → запись создаётся.
5. Ученик может открыть «Мои записи» и отменить запись.
6. Преподаватель: `/admin` → «Посещаемость» → отмечает ✅ или ❌.

## Соответствие эндпоинтам API

| Действие бота | Метод и путь |
|---|---|
| Регистрация ученика | `POST /api/v1/students` |
| Список учеников / профиль / привязка ID | `GET /api/v1/students/admin-list` |
| Создание слота | `POST /api/v1/schedule/slots?startTime=...` |
| Свободные слоты | `GET /api/v1/schedule/slots/available` |
| Запись на урок | `POST /api/v1/bookings?studentId=...&slotId=...` |
| Отмена записи | `POST /api/v1/bookings/{bookingId}/cancel` |
| Посещаемость | `POST /api/v1/bookings/{bookingId}/attendance?attended=true|false` |

Ошибки бэкенда (`400`, `409`, `500`) показываются пользователю текстом из поля `message`.

## Почему у бота своя SQLite-база

В API нет методов «найти ученика по Telegram ID» и «показать все бронирования студента».
Поэтому бот хранит:

- связь `telegram_id → student_id`;
- записи, созданные через бота: `booking_id`, слот, время, статус, посещаемость.

Следствия:

- записи, созданные через Swagger или другой клиент, не появятся в «Моих записях»;
  преподаватель может отметить их по ID вручную;
- после перезапуска бэкенда с in-memory H2 старые `studentId` могут стать недействительными —
  используйте `/link`, чтобы привязать актуальный ID;
- локальная база бота сохраняется между перезапусками (файл `data/bot.sqlite3`).

## Время

Бэкенд принимает и возвращает `LocalDateTime` без часового пояса. Бот не выполняет
преобразование времени: он показывает и отправляет время как есть. Запускайте бота и
бэкенд в одном часовом поясе (или задайте одинаковый `TZ` в окружении).

## Безопасность

В бэкенде нет аутентификации, а в боте нет серверной авторизации: доступ преподавателя
определяется только по Telegram ID из `ADMIN_IDS`. Не выставляйте сервис в публичный
интернет без дополнительной защиты. Для локальной демонстрации этого достаточно.

## Возможные проблемы

- **`BOT_TOKEN не задан`** — не создан `.env` или в нём пустой токен.
- **`Сервис временно недоступен`** — не запущен бэкенд или неверный `API_BASE_URL`.
- **Кракозябры в консоли Windows** — выполните `set PYTHONUTF8=1` (cmd) или
  `$env:PYTHONUTF8="1"` (PowerShell) перед запуском. На сообщения в Telegram это не влияет.
- **После перезапуска бэкенда профиль не найден** — H2 очистилась; используйте `/link`,
  чтобы привязать актуальный `studentId`.
- **Кнопка «устарела»** — сценарий был сброшен или бот перезапускался; откройте `/start`.

## Возможные доработки

- уведомления ученикам о новом слоте или отмене;
- запись администратором за ученика;
- перенос занятия вместо отмены;
- хранение FSM в Redis и деплой в Docker;
- авторизация API и проверка прав на стороне бэкенда.
